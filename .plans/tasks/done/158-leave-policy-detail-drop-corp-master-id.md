# 158 — Drop `corp_master_id` from `leave_policy_details` (backend + frontend)

**Where:** the top-level `hrms/` clone, branch `feature/gowtham_LeaveMasters`. The leave-policy
feature (tasks 137–149) lives there, not in `workspace-2/hrms`. Run `git -C hrms status -sb` first.

## Why
A leave-policy rule (`leave_policy_details` row) currently carries its own corp scope
(`corp_master_id`, NULL = "all corps"). This overlaps with **policy assignments**
(`leave_policy_provider_mappings`, provider type `CorpMaster`), which already decide which corp's
employees get a policy. Two ways to scope by corp is confusing: a rule scoped to corp A inside a
policy assigned to corp B silently gives employees nothing. From now on, corp targeting is done
only through assignments. A rule applies to everyone the policy is assigned to.

## Scope
Remove the **rule-level** corp column and everything that reads or writes it.

**Out of scope. Keep these as they are:**
- `EmployeeMaster.corp_master_id` and every tenancy join through `corp_masters`
  (`leave_accrual_service.py`, `assignment_service.py`, `service.py` tenancy gate, and so on).
- The `CorpMaster` **provider type** in policy assignments (`resolution.CORP`,
  `ProviderKeys.corp_id`, and the "Corp" option in `PolicyAssignments.tsx`).
- `GET /api/v1/leave/corps` + `service.list_corps` + `CorpOut` + frontend `listLeaveCorps`/`LeaveCorp`.
  Work Locations uses them too (`WorkLocations_components/hooks/useWorkLocations.ts`).
- The `corp_master_id` query param on `GET /leave-types/{id}/policy` (`router.py:102`,
  `service.get_leave_type_with_policy`). It resolves **CorpMaster provider mappings** through
  `ProviderKeys(corp_id=…)`, not the rule column. Check that it still resolves correctly once
  `_usable` loses its corp check, then leave it.
- The leave-policy UI regrouping. That is task 159, which depends on this one.
